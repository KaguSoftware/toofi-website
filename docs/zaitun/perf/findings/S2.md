# S2 findings: JavaScript bundles

Search track S2 of the [optimization plan](../../OPTIMIZATION_PLAN.md), 2026-11-22. Scope: what is in the public route's first-render JavaScript, whether the admin editor reaches public pages, unused parts of three, drei, postprocessing and GSAP, what Theatre costs at run time, duplicates. No product code changed. Scripts and the two cut experiments are in [scripts/perf/S2/](../../../../scripts/perf/S2/). The baseline is [BASELINE.md](../BASELINE.md).

## The short version

- **The admin editor ships to every public page.** The public route (`/(site)/[[...slug]]`, which renders Home, Compounds, Residences, Contact and the story pages) loads **379 KB gzip** of JavaScript at first render. One chunk of it, **165 KB, holds ProseMirror, tiptap and dnd-kit**, and the served HTML names it in a script tag on `/`, `/ar` and `/compounds`. The comment in `components/editable/client.ts` ("visitors never download editor code") is wrong (S2-1).
- **Cutting it works and is small.** Loading the editor islands through a client wrapper with `next/dynamic` takes the public first render from **370.2 to 168.8 KB gzip (−201 KB, −54%; brotli 317 → 146 KB)**, and no editor code is named in the HTML any more. The editor still loads when an editor opens edit mode. This is the whole of what "unused JavaScript" on Lighthouse mobile `/` points at.
- **n8ao is 81 KB gzip that only the top quality level uses**, and phones never reach that level (S2-2). Theatre costs 31 KB for what is a cubic curve through nine numbers (S2-3).
- Everything else is ruled out or under 5% of any target (S2-4 to S2-9).

## How it was measured

Production build of `main` at 692ea51 through the P0 rig (`scripts/perf/rig.mjs`), on the baseline's machine. Nothing here is timed, so every number is **build evidence** (bytes), not an observed request; the load trace (`trace.mjs`) has what a browser fetched. The rig refuses to run on battery; `served.mjs` only counts bytes, so it was run with `SAWAD_PERF_ALLOW_BATTERY=1`. The rig lock queued the builds behind S7, S8 and S9.

| What | How |
|---|---|
| **Real chunk sizes** | `scripts/perf/bundles.mjs`: every file in the build, gzip -9 and brotli -11 |
| **Package shares** | Next's analyzer graph (`next analyze export`), read by [graph.mjs](../../../../scripts/perf/S2/graph.mjs): compressed bytes per source file, summed per package, first render against on demand, shortest import chain to a package. The analyzer's bytes are an estimate with its own chunking: use them for shares and ranks |
| **What the page names** | [served.mjs](../../../../scripts/perf/S2/served.mjs) serves the build and lists every `static/chunks/*.js` the HTML mentions (script tags, preloads, the RSC payload), with its real gzip size and whether it contains editor code |
| **Knock-outs** | [knockout.sh](../../../../scripts/perf/S2/knockout.sh), in a throwaway worktree (`.claude/worktrees/zaitun-S2`, nothing to merge): one dependency's import replaced with an empty stand-in, rebuilt, real sizes compared **with the baseline of the same run**. They break the feature at run time: they measure weight, they are not fixes. The editor row is a real fix, kept as a patch |

One caution on the baseline: the same checkout built twice in this worktree gave a public first render of 370.2 and 379.0 KB gzip (the main checkout gave 379.1, matching BASELINE.md). The build's chunking moves by about 9 KB between runs. Every delta below is within one run, so it is not affected.

## Ruled out

| Candidate | Result |
|---|---|
| Polyfills in the HTML | `0cz1d0mv5g_q7.js` (39.5 KB gzip) is a `nomodule` script; modern browsers skip it. It is in the build's "on demand" list and in the served HTML but not in a visitor's fetches |
| Duplicate packages | None. The graph holds one version of every package, in first render and on demand |
| Admin packages reaching other public routes | There is one public route; the whole of it is S2-1. Admin routes carry them as they should: `/admin/(panel)/pages/[id]` is 215 KB (the editor page), the rest 181 KB |
| `await import()` of the editor inside the server components (`lib/content/editables.tsx`, `page.tsx`) | **No gain, 379.0 → 379.0 KB.** Next still registers the client modules in the page's first render when a server component reaches them by an async import. Only a client file that wraps them in `next/dynamic` moves them (patch `exp1-server-await-import.patch` kept as the record) |
| Unused parts of three | three.core and three.module are 181 KB of the 229 KB attributed to three, the loaders (GLTF 12 KB, KTX2 4 KB, meshopt 7 KB), OrbitControls (4 KB) and BufferGeometryUtils (1 KB) are each used. The one unused piece, the Zstandard decoder (`zstddec` 17 KB, brought in by `KTX2Loader` for UASTC), cannot be dropped without patching three; not worth it |
| drei | One file, `PerformanceMonitor` (1.5 KB), imported by its own path already. No barrel cost |
| `@react-three/postprocessing`, `postprocessing` | 72 KB (`postprocessing`) and 3 KB (`@react-three/postprocessing`): the chain uses Bloom, DepthOfField, N8AO, Noise, SMAA, ToneMapping and Vignette, so the build is what it is. If S4's proposals remove effects (DOF at blur 0, AO), the library does not shrink without a custom build |
| Theatre Studio | Only reachable through `import("@theatre/studio")` in development; not in any production chunk |
| Framework (Next and React) | 181 KB gzip analyzer share, 41% of the first render and about 80% of what is left after S2-1. Nothing to remove |

## What the first render holds after S2-1

Public route, first render 168.8 KB gzip: Next and React about 181 KB of the analyzer's count (the large majority), the app code (`components/sawad`, `lib/sawad`, the site shell and finder) and small libraries making up the rest; zod and sonner leave with the editor (not re-run through the analyzer). The next candidate is S2-5.

## Ownership gap for T

The fix needs `components/editable/lazy.tsx` (new), `components/editable/client.ts` and a test for both. **`components/editable/**` is in no track's list** (F6 owns `app/**`, `lib/**`, `templates/**`; F1 owns the experience files). T should give it to F1, since S2-1 is its biggest item.

## What to verify in the fix track

- **Edit mode**, which this search did not exercise in a browser: with the islands lazy, the editor server-renders each island as before (`next/dynamic` renders on the server) and then loads its chunk; an editor sees one extra request per first edit-mode page. The 66 tests in `components/editable` and `lib/content` pass with the experiment.
- The reference frames are unaffected (no 3D code changes); S2-3 needs the camera-path comparison and the frames.
- Measure with `trace.mjs` on the phone profile (first content, long tasks) and `lighthouse.mjs` for `/`: this search counted bytes only, because timing queues on the rig lock behind the other searches.
